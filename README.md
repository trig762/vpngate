# vpngate

Интерактивный установщик VPN-шлюза для **Ubuntu 24.04**. Клиенты подключаются к обычному WireGuard-серверу `wg0`; трафик Telegram, Meta и доменов из списка направляется через клиентский туннель AmneziaWG `awg0`. Остальной трафик выходит через обычный интернет-интерфейс.

```text
WireGuard client -> wg0 -> nftables mark 0x64 -> table 100 -> awg0
                              |
                              +-- unselected traffic -> WAN
```

## Что настраивается

- WireGuard-сервер `wg0` с автоматически созданным ключом;
- AmneziaWG-клиент `awg0` с `Table = off`;
- официальный PPA AmneziaWG и пакет `amneziawg`;
- `nftables`: динамический набор `vpn_domains4`, статический `vpn_static4`, маркировка `0x64` и NAT;
- `dnsmasq`: добавление IPv4-адресов выбранных доменов в nftables-набор;
- policy routing: правило `fwmark 0x64`, таблица `100`, маршрут через `awg0`;
- постоянный `net.ipv4.ip_forward=1`;
- systemd-запуск обоих туннелей, nftables, dnsmasq и таблицы маршрутизации;
- резервные копии, журнал установки и проверка результата;
- помощник для создания клиентских конфигураций WireGuard.

Установщик не меняет маршрут по умолчанию самого сервера. Секретные ключи вводятся без отображения, не попадают в журнал и сохраняются в файлах с режимом `0600`.

## Требования

- чистая или уже используемая Ubuntu Server 24.04;
- доступ `root`/`sudo` и интернет;
- открытый входящий UDP-порт для `wg0` (по умолчанию `51820`);
- экспортированная конфигурация AmneziaWG-клиента: адрес, приватный ключ, публичный ключ сервера, endpoint и параметры `Jc/Jmin/Jmax/S1/S2/H1-H4`;
- отсутствие другого DNS-сервиса, занимающего адрес `wg0`:53.

Если используется UFW или отдельный firewall, разрешите UDP-порт `wg0`, DNS с `wg0` и пересылку трафика. Установщик добавляет собственную таблицу `inet vpngate`, но намеренно не удаляет сторонние правила.

## Установка

```bash
git clone https://github.com/trig762/vpngate.git
cd vpngate
chmod +x install.sh
sudo ./install.sh
```

Перед изменениями выводится сводка и требуется подтверждение. Поддержка других выпусков Ubuntu намеренно заблокирована, чтобы не применять непроверенные команды управления пакетами.

При повторном запуске установщик переиспользует приватный ключ `wg0` и сохраняет существующие секции `[Peer]`. Изменяемые файлы копируются в `/var/backups/vpngate/<UTC timestamp>/`, список файлов находится в `MANIFEST`. Журнал: `/var/log/vpngate-install.log`.

## Параметры AmneziaWG

Значения следует переносить из рабочей клиентской конфигурации без изменений. `Jc` должен быть в диапазоне 1–128, `Jmin < Jmax <= 1280`, `S1 <= 1132`, `S2 <= 1188`, а `H1-H4` должны отличаться. Не используйте показанные установщиком значения по умолчанию вместо серверных параметров, если они уже указаны в экспортированном профиле.

Установщик поддерживает классический набор параметров AWG 1.x. Профили AWG 1.5/2.0 с полями `I1-I5` в этой версии не поддерживаются: не продолжайте установку с таким профилем.

## Добавление клиента WireGuard

```bash
sudo vpngate-add-client
```

Помощник запросит имя, свободный IPv4-адрес из сети `wg0` и публичный адрес шлюза. Он:

1. создаст ключи и PSK;
2. добавит peer в `/etc/wireguard/wg0.conf` без остановки интерфейса;
3. сохранит клиентский файл в `/etc/vpngate/clients/<name>.conf`;
4. выведет QR-код в терминал.

Скопируйте клиентский файл безопасным способом и удалите лишние копии: он содержит приватный ключ.

## Списки направлений

Статические диапазоны устанавливаются в:

- `/etc/nftables.d/vpngate-static/telegram.nft`;
- `/etc/nftables.d/vpngate-static/meta.nft`.

Исходные шаблоны находятся в [`config/static`](config/static). Префиксы сервисов меняются со временем; проверяйте их по официальным данным владельца сети. После редактирования сначала проверьте, затем примените правила:

```bash
sudo nft --check --file /etc/nftables.conf
sudo systemctl reload nftables
```

Домены задаются строками `nftset=` в `/etc/dnsmasq.d/vpngate.conf`. После изменений:

```bash
sudo dnsmasq --test
sudo systemctl restart dnsmasq
```

В динамический набор попадают только ответы DNS, полученные клиентами через DNS шлюза (`10.66.66.1` по умолчанию). DoH/DoT на клиентах обходит этот механизм, однако статические IP-наборы продолжают работать.

## Проверка и диагностика

```bash
sudo /usr/local/libexec/vpngate-check
sudo nft list table inet vpngate
ip -4 rule show
ip -4 route show table 100
sudo wg show wg0
sudo awg show awg0
journalctl -u awg-quick@awg0 -u vpngate-policy -u dnsmasq --since today
```

Ожидаемое правило маршрутизации содержит `fwmark 0x64 lookup 100`, а таблица 100 — `default dev awg0`.

Для проверки выбранного маршрута с уже разрешённым IPv4-адресом:

```bash
ip route get 149.154.167.99 mark 0x64
```

## Файлы на сервере

| Назначение | Путь |
|---|---|
| WireGuard server | `/etc/wireguard/wg0.conf` |
| AmneziaWG client | `/etc/amnezia/amneziawg/awg0.conf` |
| nftables | `/etc/nftables.d/vpngate.nft` |
| DNS/domain routing | `/etc/dnsmasq.d/vpngate.conf` |
| Policy routing | `/usr/local/libexec/vpngate-policy` |
| Persistent service | `/etc/systemd/system/vpngate-policy.service` |
| Installer log | `/var/log/vpngate-install.log` |

## Важные замечания

- Скрипт изменяет сетевые настройки удалённого сервера. Держите открытой вторую SSH-сессию и убедитесь, что есть консольный доступ.
- Установщик не открывает порт в панели облачного провайдера/security group.
- В этой версии маршрутизируется только IPv4. IPv6 не раздаётся клиентам, чтобы исключить обход выбранной политики.
- Статические диапазоны — стартовый список, а не гарантия полного покрытия всех адресов Telegram/Meta.
